# v0.1 Acceptance Tests

**Status:** Specified cases. No compiler in this repository executes them yet.  
**Normative inputs:** LLD 01–05, including the v0.1 resolutions recorded there.

Each case becomes an executable test in the compiler phase that owns it. A case listed here is not a passing test until that implementation exists and runs it.

Phases:

- **Lexer** — tokens and lexical diagnostics.
- **Parser** — grammar, including prefix versus postfix and rejection of deferred operators.
- **Semantic** — types, imports, `main`, forward calls, and call-site conversion.
- **Lowering** — typed AST or equivalent explicit conversion nodes, then Rust that receives the target type.
- **Runtime** — formatting and increment behavior once those policies are implemented.

## 1. Import and call token stream

**Phase:** Lexer

Source:

```grf
import grf.io;
io.println("Hello");
```

Expected kinds:

```text
KwImport
Identifier("grf")
Dot
Identifier("io")
Semicolon
Identifier("io")
Dot
Identifier("println")
LeftParen
StringLiteral("Hello")
RightParen
Semicolon
Eof
```

`StringLiteral("Hello")` is the kind plus decoded text. The lexeme keeps the quotes.

**Phase:** Semantic. Reject a program whose only output call is written `grf.io.println("Hello");` after `import grf.io;`.

## 2. `auto` is a keyword

**Phase:** Lexer

| Source fragment | Expected |
| --- | --- |
| `auto` | `KwAuto` |
| `automation` | one `Identifier("automation")` |
| `int auto = 1;` | `KwInt`, `KwAuto`, `Equal`, `IntegerLiteral("1")`, `Semicolon` |

`auto` must not appear as `Identifier`.

**Phase:** Semantic. Reject bare `auto` and inference-style declarations:

```grf
auto age = 21;
```

Accept a target-directed declaration whose type is written explicitly:

```grf
auto int age = 21;
```

The target type is `int`, canonical `int64`. This is not inference.

## 3. `++` and `--`, and deferred operators

**Phase:** Lexer

| Source fragment | Expected tokens |
| --- | --- |
| `index++` | `Identifier("index")`, `PlusPlus` |
| `++index` | `PlusPlus`, `Identifier("index")` |
| `index--` | `Identifier("index")`, `MinusMinus` |
| `--index` | `MinusMinus`, `Identifier("index")` |
| `index += 1` | `Identifier`, `Plus`, `Equal`, `IntegerLiteral` |
| `index -= 1` | `Identifier`, `Minus`, `Equal`, `IntegerLiteral` |
| `index *= 1` | `Identifier`, `Star`, `Equal`, `IntegerLiteral` |
| `index /= 1` | `Identifier`, `Slash`, `Equal`, `IntegerLiteral` |
| `index %= 1` | `Identifier`, `Percent`, `Equal`, `IntegerLiteral` |
| `a->b` | `Identifier`, `Minus`, `Greater`, `Identifier` |
| `a:b` | unexpected character at `:` |
| `a?b` | unexpected character at `?` |

**Phase:** Parser. Accept prefix and postfix `++` and `--` in expression position, including the update clause of:

```grf
loop (int index = 0; index < 10; index++) {
    io.println(index);
}
```

Accept `+=`, `-=`, `*=`, `/=`, `%=`, `**=`, `//=`, and `**`. Reject `->`, `:`, and `?`. `//` remains a line comment.

**Phase:** Semantic.

- `++` and `--` require a mutable integer variable.
- Reject increment of a `const` integer, a non-integer, or a non-variable expression such as `(index + 1)++`.
- `++index` evaluates to the updated value. `index++` evaluates to the previous value, then increments. `--` mirrors that order.

**Open decision:** integer overflow is unspecified. Tests must not expect silent wrapping. Add the overflow cases only after the policy is frozen.

## 4. Canonical type aliases

**Phase:** Semantic

```grf
int64 source = 42;
int destination = source;
```

Accept. `int` and `int64` are the same canonical type `int64`. No conversion node is required.

Accept the same pattern for `uint` / `uint64` and `flt` / `flt64`.

`int32` and `int64` are not aliases. A test that assigns one to the other with no conversion must not be treated as the alias success case. The cross-width conversion table is still an open decision, so this suite does not invent an implicit widening or a rejection code for it. Diagnostics may mention the spelling written in source. Type equality uses the canonical type.

## 5. Import collisions and import shape

**Phase:** Parser or semantic

Reject:

```grf
import grf.io.print;
```

Reject:

```grf
import grf.io;
import other.io;
```

The diagnostic identifies the second binding of the local name `io`.

Accept two different library names:

```grf
import grf.io;
import coolDev.netHttp;
```

Calls use `io` and `netHttp`. Import aliases are rejected; there is no alias syntax to accept.

Repeating `import grf.io;` is a redundant-import diagnostic. It is not an idempotent no-op. The diagnostic says that `grf.io` was imported more than once.

Imports after the first declaration are rejected:

```grf
void main() {
}

import grf.io;
```

## 6. v0.1 keyword inventory

**Phase:** Lexer

These lexemes are keywords: `auto`, `const`, `void`, `int`, `uint`, `flt`, `int16`, `int32`, `int64`, `uint16`, `uint32`, `uint64`, `flt32`, `flt64`, `bln`, `chr`, `str`, `if`, `else`, `loop`, `break`, `continue`, `return`, `import`, `true`, `false`.

These lexemes are identifiers: `class`, `private`, `this`, `public`, `new`, `constructor`, `library`, `grf`, `io`, `fileIo`.

`If` is an identifier. `if` is `KwIf`.

## 7. Sketch constructs that v0.1 rejects

**Phase:** Parser or semantic. The root `test.grf` sample must not contain these forms. Separate negative fixtures must reject them:

- `int[num.length()] arr = [];`
- `library fileOPS { }`
- `constructor(str path) { }`
- `new string(path)`
- a type named `string`
- `enumerate()`
- `import grf.string;` unless a later manifest actually defines that library
- an `import` that appears after a declaration

Rejecting these forms is the test. Do not add the features so a scratch file can compile.

## 8. `main` and forward calls

**Phase:** Semantic

Accept one entry file whose only entry point is `void main()` with no parameters. Accept a call to a top-level function declared later:

```grf
import grf.io;

void main() {
    io.println(square(5));
}

int square(int value) {
    return value * value;
}
```

Declaration collection happens before body checking.

Reject:

- a file with no `main`
- two `main` functions
- `int main()`
- `void main(str args)`
- `void main(int argc, str argv)`

## 9. Call-site `auto T` conversion

**Phase:** Semantic and lowering

```grf
str greet(auto str msg) {
    return f"Hello {msg}";
}

void main() {
    io.println(greet(123));
}
```

Expected checks:

1. `greet`'s parameter type inside the body is `str`.
2. The call `greet(123)` inserts an explicit conversion from the integer argument to `str` before the call.
3. Generated Rust passes a `String` into `greet`. It does not pass a bare integer for the Rust callee to format.
4. `io.println` is resolved from `grf.json` as `auto str` and uses the same call-site conversion. The Rust path `graphite_core::io::println` receives a `String`.

Reject an argument whose type has no conversion to the target. The failure must not invent a value.

**Open decision:** the conversion-failure mechanism for invalid text, overflow, and unsupported pairs is unspecified. Tests for those failures should assert rejection only, until the diagnostic or runtime form is frozen.

## 10. Interpolation matches `auto str`

**Phase:** Semantic, lowering, and runtime

```grf
str message = f"Age: {age}, active: {isActive}";
```

Each interpolation uses the same formatting implementation as conversion to `auto str`.

v0.1 sources that must format:

- `str`, unchanged
- signed and unsigned integers
- floating-point values
- `bln`, as the text `true` or `false`
- `chr`

A direct comparison test must show that `auto str value = expr;` and `f"{expr}"` produce the same text for the same primitive `expr`.

`123` formatted as `str` is `123`, matching the conversion example in LLD 02.

Reject interpolation of a class, collection, or other type outside the primitive set. That diagnostic is compile-time.

**Open decision:** exact floating-point and `chr` spellings, escape sequences, and literal brace escaping. Do not lock those spellings in tests until the LLDs freeze them. Boolean text `true` / `false` and the integer example `123` are frozen.
